# Final launch report

**Date:** 2026-09-20 · **Version:** 1.0.0 · **Branch:** `main`

Where InsightFlow AI stands at the end of the productionisation pass. The
companion document, [PRODUCTION_AUDIT.md](PRODUCTION_AUDIT.md), records where it
stood at the beginning; every finding raised there is accounted for below.

Nothing in this report is claimed without having been run.

---

## 1. Product status

**Launch-ready**, with the limitations in §10 stated rather than hidden.

An AI business operations analyst. A business uploads a spreadsheet of orders
and gets back what changed, where it came from, how large it was, what
coincided with it, what might explain it, and what to check next — with the
calculation behind every figure openable in one click.

The discipline that makes it worth trusting: **every number is computed in
Python and recorded as evidence before a language model sees anything.** The
model phrases findings; it never produces them, and what it writes is validated
against those findings before it is shown. Turn the model off entirely and the
product still works — the whole test suite runs that way.

## 2. Architecture

```
Browser ──── same-origin fetch, httpOnly cookie
   │
   ▼
Next.js 15.5 (App Router)                          → Vercel
   ├ /api/auth/*        owns the session cookie
   └ /api/backend/[..]  authenticating reverse proxy
   │  Authorization: Bearer · X-Real-Client-IP
   ▼
FastAPI (Python 3.11)                              → container host
   ├ analytics/  deterministic engine — the source of every number
   ├ ai/         provider abstraction + guardrails
   ├ jobs/       in-process analysis runner
   └ api/v1/     48 routes
   ▼
PostgreSQL  ·  filesystem storage for uploads
```

**Measured:** backend 19,361 lines of Python, frontend 12,333 lines of
TypeScript. 48 backend routes, 17 frontend pages, 8 route handlers.

The browser never contacts the backend. That single decision keeps the session
cookie first-party, keeps access tokens out of JavaScript's reach, and removes
CORS from production entirely.

## 3. What changed

### Correctness

| | |
| --- | --- |
| **Weekly resampling returned all zeros** | Buckets were keyed by period *start* while the gap-filling reindex was generated at week *end*, so the two index sets had no members in common and `reindex(fill_value=0.0)` replaced every real figure. Any dataset viewed at weekly grain showed a flat zero revenue line, presented as a finding. Daily, monthly, and quarterly aligned by coincidence. Now generated by the same `Period` machinery that produces the keys, with a test asserting every grain preserves the total. |
| **Dates were read as fabricated figures** | The guardrail's number regex pulled `-03` and `-14` out of `2026-03-14` and reported them as invented. Every anomaly and period comparison names a date, so in practice the guardrail rejected nearly any answer that said *when* something happened — silently falling back while logging that the model had fabricated figures it never wrote. Dates and times are now removed before extraction. |
| **Three kinds of computed percentage were never recorded** | Segment shares, contribution percentages, and the smallest-segment row were quoted in prose while carried only inside `Evidence.detail`, where `evidence_values()` never looked. Unopenable for the reader, and grounds for discarding a correct model answer that repeated them. |
| **Timestamps lost their timezone** | SQLite returns naive datetimes, which serialise without a `Z`, which a browser reads as local time. A new `UTCDateTime` column type re-attaches UTC on the way out. |
| **Relative times were one unit too large** | Each threshold was paired with the unit named beside it rather than the one below it, so an analysis finished five hours ago read "5 days ago". |
| **Transactions were held across the model call** | Both endpoints that call a model did so inside an open write transaction lasting 60–180 seconds. On SQLite that starved every other writer into "database is locked". Both now commit first and write their result separately. |
| **A working answer was reported as an outage** | A question answered in 306 seconds reached the browser as *"we could not reach the analysis service"*. Node stops waiting for response headers at 300 seconds and a route handler cannot raise that, so the proxy gave up six seconds before the backend succeeded — discarding the answer and pointing the reader at a healthy service. The budget was the cause: `(AI_MAX_RETRIES + 1) * AI_TIMEOUT_SECONDS` was 360 seconds, over the ceiling before the first token. The per-call budget is now 120, capping a call at 240 so the AI layer times out first and takes its own tested fallback path. The message is fixed independently: a timeout is named as one, with a 504, because Node hides the real cause behind an opaque "fetch failed". 15 tests pin the classification. |

### Security

| | |
| --- | --- |
| **Rate limiting was bypassable and broken at once** | `X-Forwarded-For` was trusted unconditionally: rotating it defeated the auth budget, and behind the Next.js proxy the backend saw only Vercel, so one budget was shared by every user. A forwarded address is now believed only with a shared secret or a declared proxy count, and read from the right-hand end. 12 tests pin it. |
| **No CSP or HSTS on the frontend** | Added, including `frame-ancestors 'none'` and `connect-src 'self'` — unusually tight for an app with an API, and correct here. |
| **Audit logs recorded a spoofable address** | Now the trusted one. An audit trail pointing wherever the attacker chose is worse than none. |
| **No secret scanning** | gitleaks over full history in CI, with the two test-account passwords allowlisted by exact literal and exact path. |
| **Dependency advisories** | Eight, including two critical. Four fixed by upgrading Next, vitest, vite, and postcss; four remain, two of them inside Next's own bundle (§10). |

### Product

| | |
| --- | --- |
| **The demo did not exist** | "View demo" linked to `/login?demo=1`, which nothing read. `/demo` now opens a throwaway workspace with the sample data already loading — no account, no password, no file. Isolated per visitor, expiring, with no credential anywhere. |
| **Investigation held the page behind the model** | The evidence is complete before a token is generated, so it is now returned immediately and the prose fetched separately and cached. Reopening an investigation previously downgraded its prose silently; it no longer does. |
| **Landing page was missing four sections** | Problem, use cases, FAQ, and a real footer. Still no invented customers, testimonials, logos, or awards. |
| **Prose duplicated itself** | The engine writes the narrative by joining the findings, and both were rendered. |
| **Currency was missing from narrative figures** | "Revenue was 193,032.93" now reads "USD 193,032.93". |
| **No SEO assets** | Generated sitemap and robots that name the real host, a social preview card, and an Apple touch icon. |
| **`npm run lint` hung forever** | ESLint 9 with a legacy config. Migrated to flat config; lint now terminates and passes at zero warnings. |
| **Lint was not clean** | 7 errors and 3 warnings, all fixed. |

## 7. Deployment architecture

| Layer | Choice | Why |
| --- | --- | --- |
| **Frontend** | **Vercel** | A standard Next.js deployment. Root directory `frontend`; everything else detected. Verified with a production build on the final code. |
| **Backend** | **A container host** (Render, Fly.io, Railway, or a VPS) | Not Vercel, deliberately: analysis is a multi-second pandas workload on a background thread pool, uploads need a persistent volume, and the job runner keeps state in-process. `backend/Dockerfile` is multi-stage, non-root, health-checked, and applies migrations on start-up. |
| **Database** | **PostgreSQL** (Neon, Supabase, or the host's) | SQLite is development-only, and production start-up refuses to run without `DATABASE_URL`. |
| **AI** | **Configurable, and optional** | `ollama`, any OpenAI-compatible endpoint, or `none`. The product is fully functional with `AI_ENABLED=false`, and the whole test suite proves it continuously. |

The two halves connect over HTTPS with a bearer token attached server-side.
**No CORS configuration is needed in production**, because the browser only
ever talks to its own origin.

`PROXY_SHARED_SECRET` must be set identically on both halves. Without it the
backend rate-limits on the frontend's address, so every user of the product
shares one budget.

## 10. Remaining limitations

Stated plainly. Each is a decision, not an oversight.

**Not implemented**

- **Transactional email.** Password reset issues a valid token and, in
  development, logs it so the flow is testable. In production the token is
  issued and nothing delivers it.
- **Team workspaces.** `WorkspaceMember` and `WorkspaceRole` exist and are
  enforced; there is no invitation flow.
- **PDF export.** Reports print to PDF through the browser.
- **Scheduled analysis, alerting, forecasting, incremental uploads,
  connectors.** Listed in the README roadmap.
- **Legacy `.xls`.** Rejected rather than parsed. `xlrd` on OLE2 is meaningful
  attack surface for a format almost nobody exports; the message says to
  re-save as `.xlsx`.

**Accepted trade-offs**

- **Rate limiting is per process.** Behind more than one backend replica the
  budget multiplies by the replica count. Redis would fix it and is not yet
  earned.
- **The job runner is in-process.** A thread pool plus the `analyses` table.
  Reviewed during this pass and deliberately kept: progress is committed per
  stage so it is durable and pollable, orphaned jobs are reconciled at
  start-up, and the constraint it imposes (`--workers 1`, scale by replica) is
  documented and enforced in the Dockerfile. Celery and Redis would add two
  failure modes to fix zero observed problems.
- **Two dependency advisories remain**, both inside Next's own bundled tree: a
  high-severity postcss source-map issue at `node_modules/next/node_modules/postcss`,
  and a moderate missing-origin-verification issue in the Next **development**
  server. Neither is reachable by a user of the deployed product, and neither
  can be fixed from this repository — they need a Next release.

**Not claimed**

- **No compliance certification.** No SOC 2, ISO 27001, HIPAA, or GDPR
  certification is held, and the product says so on the landing page, in the
  README, and in `SECURITY.md`.
- **No trademark.** The name and mark are not registered. Anyone taking this
  to a public launch must verify domain and trademark availability
  independently.
- **No production deployment exists yet.** The frontend is Vercel-ready and the
  backend is container-ready, both verified locally; no live URL has been
  created, so none is claimed.

**Known guardrail gaps** — documented in
[AI_GUARDRAILS.md §9](AI_GUARDRAILS.md#9-what-this-does-not-cover). The
guardrails are numeric and causal; a non-numeric misstatement or a hallucinated
segment name would not be caught by them.
